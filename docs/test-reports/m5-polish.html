T02 Reminders Fixed

Settings → Reminders → on

Expected
A short explanation first (FR-86), then 7 days of reminders, with today skipped once something is logged (FR-80)
Notes
6 daily reminders were scheduled (today was already logged), and Android held the alarms. Each start scheduled everything twice; it now waits for the week's check-in to load and schedules once. The reminder rows had no spacing between them.
T03 Auto backup Fixed

Turn on automatic weekly backup and pick Download/Kakeibo

Expected
Android asks for access to that folder only; a backup is written at once; the Home banner goes (FR-73)
Notes
Android 11 doesn't allow the Download folder itself, so a Kakeibo folder was made inside it, as the PRD suggests. The first try wrote 3 copies at once, because saving the settings re-ran the backup check; fixed with a test, and the 2 extra files were deleted. Restarting the app no longer writes another. The folder picker screenshot is left out because it shows your folders.

Still open

  • A reminder firing on screen. Android had the alarms (18 entries), but I didn't wait for one to appear: the time picker is hard to drive by script. Your 9:00 PM reminder tomorrow is the real test.
  • Fingerprint unlock. The phone offers it, but turning it on needs your finger on the sensor. Try Settings → Security → Unlock with fingerprint after turning the lock on.
  • Permission denied path. Android 11 doesn't ask for notification permission (13 and later do), so the “Notifications are off” note was checked by code review only.
  • Reboot. Reminders are re-scheduled after a restart by Android's boot receiver; not tested by restarting the phone.
  • 200% font size. Not tried: it means changing a system setting on your phone.

Not covered by this run

  • Reset app (the last-resort wipe when the PIN and code are both lost). It reuses delete-all, which M4 tested.
  • Changing the backup folder, and the “can't reach the folder” message after access is removed.
  • Exporting diagnostics through the share sheet (the log itself was read directly).

Automated tests

  • flutter analyze: no issues.
  • flutter test: 101 passed, 27 new in M5.
  • My stats: streaks (ending today or yesterday), best streak, days logged, entries a day, and goals, reflections and savings rate from closed months.
  • Reminders: the 7-day window, today skipped once logged, past times skipped, stable ids, the optional evening reminder, the weekly check-in on the last day of the week, plan and reflect at month start and end, and safe time parsing.
  • App lock: only salted hashes stored, PIN checks, the attempt countdown, lockouts of 30 s → 1 min → 5 min, the recovery code ignoring case and dashes, a new code replacing the old one, clearing, and PIN format.
  • Auto backup: due weekly, the 14-day banner, written and pruned to 8, overlapping runs writing one file, lost access and failed writes reported, not thrown.
  • Diagnostics: the log rotates at its size limit, keeps 3 files and exports oldest first.
  • Widgets: a locked app hides Home until the right PIN; the recovery code leads to a new PIN; turning the lock on walks through PIN, mismatch and recovery code; screen readers can activate tabs, pillar tiles, bars and PIN keys.
